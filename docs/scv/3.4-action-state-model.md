# Phase 3 — 操作状态机：按钮操作 / 模型槽位 / 图片索引（FR23–FR25，2026-10-17）

来源：用户反馈「第一次启用模型卡顿，按钮要有 loading，超时提示失败并写日志，所有按钮操作埋点，记录最慢 1000 次」
「相似度阈值可配置」「这张图片还没有建立索引」提示不准；要求「状态机一定要设计好，中间状态一定要明确」。

决策（`1.2-questions.md` Q14–Q16）：超时按操作类型区分；慢操作存独立埋点库并可导出；顺序 埋点 → 阈值配置 → 索引提示。

---

## 1. 按钮操作状态机（ActionState，FR23）

每个可点击操作有一个**操作键**（如 `settings.model.activate:siglip2-base@1`、`panel.delete:42`）。同一个键同时最多一个执行中。

### 状态

| 状态 | 含义 | UI | 持久化 |
|---|---|---|---|
| `idle` | 没有进行中的操作 | 按钮可点 | 否 |
| `running(startedAt)` | 已开始，等待结果 | 按钮显示转圈、不可点；超过 0.3 s 才显示转圈（避免闪烁） | 否 |
| `succeeded(duration)` | 在期限内完成 | 按钮恢复；必要时短暂提示 | 否 |
| `failed(message)` | 在期限内抛错 | 按钮旁红字说明原因，直到下一次操作 | 否 |
| `timedOut(limit)` | 超过期限仍未完成 | 红字「操作超时（60 s），已记录日志」 | 否 |
| `cancelled` | 用户取消（仅支持取消的操作，如下载） | 灰字「已取消」 | 否 |

### 转换

| 当前 | 事件 | 守卫 | 下一 | 副作用 |
|---|---|---|---|---|
| idle / succeeded / failed / timedOut / cancelled | `start` | 同键无 running | running | 记开始时间；启动操作与期限计时 |
| running | `start` | — | running（**忽略**） | 不重复执行（防连点） |
| running | `completed` | 未超时 | succeeded | 埋点 outcome=succeeded |
| running | `threw(error)` | 未超时 | failed | 埋点 outcome=failed；写日志 |
| running | `deadline` | — | timedOut | 埋点 outcome=timedOut；写日志 |
| running | `cancel` | 操作可取消 | cancelled | 取消底层任务；埋点 outcome=cancelled |
| timedOut | `completed` / `threw`（迟到结果） | — | timedOut（**不变**） | 埋点 `action.late_result`（含实际耗时）；**业务结果照常生效**（例如模型最终启用了，界面靠重新读取设置显示真实状态，不靠这个迟到事件翻转按钮状态） |

**同一终态多成因**：失败 = 抛错（原因文字）/ 超时（期限）/ 取消（用户）——三者在 UI 和埋点里区分，不合并成「失败」。

### 期限（Q14）

| 操作 | 期限 |
|---|---|
| 启用 / 切换 / 停用模型 | 60 s |
| 下载模型 | 无期限（有进度和取消） |
| 复制、删除、置顶、清空、清理向量、录制快捷键、排除 App、运行诊断、导出日志 | 10 s |

### 重启

全部为内存状态，重启回到 `idle`。进行中的操作随进程结束；其业务效果以存储为准（例如模型是否启用看 `settings`）。

## 2. 模型槽位状态机（ModelSlotState，FR23 / R8 / FR26）

**三个独立槽位**（FR26，2026-10-17 用户反馈「启用 Apple Vision 后 SigLIP2 被停用，状态不应一起控制」）：

| 槽位 | 用途 | 可选模型 | 未启用时 |
|---|---|---|---|
| `image` | 用文字描述找图片 | SigLIP2、MobileCLIP S0/S2/B-LT | 图片只能按图中文字搜 |
| `text` | 按意思找文本 | Multilingual E5 等 | 文本只能按关键词搜 |
| `similar` | 详情里的相似图片 | Apple Vision 特征 | **跟随 image 槽**（用 image 槽模型的向量） |

三个槽位各自一台下表的状态机，互不影响：启用其中一个不会改变另外两个。
迁移：旧设置中 `active_model` 若是 similar 槽的模型（Apple Vision），启动时移到 `active_similar_model`，image 槽置为未启用（一次性，幂等）。

| 状态 | 含义 | 搜索使用 | 设置页 |
|---|---|---|---|
| `inactive` | 未启用 | 不参与 | 「未启用」 |
| `activating(target, previous)` | 正在加载 target（加载模型 → 从库读向量 → 建索引） | **继续使用 previous**（若有） | target 行转圈；本槽其它「启用」按钮不可点 |
| `active(model)` | 已启用 | 使用 model | 「已启用」 |
| `failed(target, error, previous)` | target 加载失败 | **继续使用 previous**（若有） | 红字原因；可重试 |

| 当前 | 事件 | 守卫 | 下一 | 副作用 |
|---|---|---|---|---|
| inactive / active(p) / failed(_, _, p) | `activate(t)` | t 已安装、族支持 | activating(t, p) | 后台加载（先准备，后切换） |
| activating | `activate(*)` | — | activating（**拒绝**） | 按钮不可点；CLI 返回「正在启用」 |
| activating(t, p) | `loaded` | — | active(t) | **原子切换**：引擎、worker、settings 一起换；回填入队 |
| activating(t, p) | `loadFailed(e)` | — | failed(t, e, p) | 不写 settings；p 保持可用 |
| active(m) | `deactivate` | — | inactive | 引擎、worker、settings 清空 |
| 任意 | `syncWithStore` 发现 settings 与内存不同 | 非 activating | → activating(settings 值) | R8：CLI 改动被 App 接管 |

**中间态的不变量**：activating 期间，搜索结果与索引任务都只属于 previous；settings 只在 `loaded` 后改写（进程在 activating 中被杀 → 重启后仍是 previous）。

## 3. 图片索引状态（派生，FR25）

对「当前选中的图片 × **相似图片实际使用的模型**」（similar 槽已启用则用它，否则用 image 槽），由 `embeddings` 与 `index_jobs` 派生，**不存储**：

| 状态 | 判据 | 详情区显示 |
|---|---|---|
| `noModel` | similar 槽与 image 槽都 inactive | 「启用图片搜索模型或相似图片模型后可显示相似图片」 |
| `slotBusy` | 所用槽位 activating | 「正在启用 X…」 |
| `indexed` | 有该模型的向量 | 显示相似图片（无则「没有相似图片」） |
| `queued` | 有 pending 任务 | 「正在排队建立索引…」 |
| `running` | 有 running 任务且租约未过期 | 「正在建立索引…」 |
| `failed(error)` | 有 failed 任务 | 「建立索引失败：原因」+ 可重试 |
| `missing` | 以上都不是（不应出现） | 「尚未建立索引」并自动入队（自愈） |

**刷新**：收到 `indexProgress` / `modelChanged` 事件且当前选中的是图片时重新派生，不需要用户切换选中项。

## 4. 埋点（FR23）

每次按钮 / 快捷键操作结束（任一终态）写一条：

| 字段 | 内容 |
|---|---|
| `name` | 静态操作名（`settings.model.activate`、`panel.copy` …） |
| `detail` | 可选标识（模型 id、条目 id）——**不含剪贴板内容** |
| `started_at` / `duration_ms` | 开始时间、耗时 |
| `outcome` | succeeded / failed / timedOut / cancelled |

- 每条写入滚动日志（`action.done name=… ms=… outcome=…`）。
- 同时写入 `logs/telemetry.sqlite`，**只保留耗时最长的 1000 条**（插入后删除第 1001 名以后，同一事务）。schema 见 `2.2-data-contracts.md`「埋点库」。
- 报告：`ClipVault --slow-ops [--limit N]`；「导出日志」附带 `slow-ops.txt`。
- 横切约束（静态测试）：App 界面里的 `Button(` 必须是 `TrackedButton`，或其动作经 `ActionCenter.perform` 执行。

## 5. 回车粘贴（FR28，Q19）

面板是不抢焦点的浮动面板：打开期间前台 App 不变，光标仍在原处。打开面板时记下前台 App（`target`，pid）。

### 状态（中间态显式）

| 状态 | 含义 |
|---|---|
| `copying` | 正在把条目写回剪贴板（`copyBack`，自写不入库） |
| `copyFailed` | 终态：写回失败，面板不关，按 FR23 显示原因 |
| `closing` | 已写回，面板正在隐藏 |
| `deciding` | 面板已隐藏，按纯函数 `PasteDecision` 决定粘贴还是只复制 |
| `posting` | 已发送 ⌘V（CGEvent 键盘事件，发到当前前台 App） |
| `pasted` | 终态：提示「已粘贴」 |
| `copiedOnly(reason)` | 终态：提示「已复制」+ 原因（见下表） |

### PasteDecision（纯函数，穷举测试）

输入：是否按住 ⌘、是否有辅助功能权限、是否处于安全输入（密码框）、当前前台 pid、`target` pid。

| 条件（按顺序） | 结果 | 提示 |
|---|---|---|
| ⌘回车 | `copiedOnly(.commandHeld)` | 已复制 |
| 无辅助功能权限 | `copiedOnly(.notTrusted)` | 已复制 · 开启「辅助功能」后回车可直接粘贴 |
| 安全输入开启（密码框等，系统会丢弃合成按键） | `copiedOnly(.secureInput)` | 已复制 · 当前输入框不允许自动粘贴 |
| 不知道 `target`，或前台已不是 `target`（切走 / 退出） | `copiedOnly(.targetChanged)` | 已复制 · 原 App 已不在前台 |
| 其余 | `paste` | 已粘贴 |

### 约束
- **先写回、后粘贴**：⌘V 只在 `copyBack` 成功之后发送；写回失败绝不发 ⌘V（否则会粘贴旧内容）。
- **只粘到原 App**：发送前再核对一次前台 pid，防止把内容贴进别的 App。
- **隐藏后再发**：面板 `orderOut` 之后等 ≤ 150 ms（每 10 ms 查一次面板不再是 key、前台仍是 `target`），超时按当时状态决定，避免 ⌘V 落在面板自己的搜索框里。
- **权限失效检测**：发送前调用 `AXIsProcessTrusted()`；系统在授权后撤销的情况下事件会被静默丢弃——无法探测，列入已知限制。
- 埋点：`panel.paste.enter`（结果写在 detail：`pasted` / `copied:<reason>`）、`panel.copy.cmd_enter`。

### 重启
无持久状态；进程在任一中间态被杀，剪贴板内容要么已写回（用户可手动 ⌘V），要么未写回，均不产生重复条目。
